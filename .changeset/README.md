# Changesets

Hello and welcome! This folder has been automatically generated by `@changesets/cli`, a tool to manage versioning and changelogs. Read the full documentation at https://changesets.dev.

We also have a quick list of common questions to get you started engaging with this project in our [FAQ](https://changesets.dev/faq).

## Adding a changeset

Every pull request that changes the published package should include a changeset:

```bash
pnpm changeset
```

Pick the bump type (`patch`, `minor`, `major`) and describe the change. That Markdown file is committed alongside your code.

## How a release happens

`.github/workflows/release.yml` runs [changesets/action](https://github.com/changesets/action) on every push to `main`:

1. While unreleased changesets exist, the action updates the **“chore: version packages”** pull request. That PR applies the version bumps, regenerates `CHANGELOG.md`, and deletes the consumed changeset files.
2. Merging that PR leaves `main` with no pending changesets, so the next run of the workflow publishes the packages to npm, tags the release, and creates a GitHub release.
